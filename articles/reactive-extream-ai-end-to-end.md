## はじめに

「マーブル図って、読むものじゃなくて**組み立てるもの**では？」

RxJS のドキュメントを眺めていて浮かんだ、それだけの思いつきでした。そこから Claude Code に投げ続けて、94ステージのパズルゲームとして公開しました。

https://hummer98.dev/rx-pipeline-puzzle/

https://github.com/hummer98/rx-pipeline-puzzle

この記事は「AIでゲームを作った話」ではありません。**動くものができた後に何が残っていて、それをAIとどう片付けたか**の記録です。個人開発が止まるのは実装力ではなく、たいていその先だからです。

## 何を作ったか

ReactiveExtream（Extream = Extreme × Stream）という、RxJS のオペレータをパズルとして学ぶゲームです。

1. **観察する** — 入力ストリームと正解ストリームをタイムライン上で見比べる
2. **組み立てる** — `map` / `filter` / `debounceTime` / `switchMap` などを並べ、パラメータを調整する
3. **差分を見る** — 出力が即座に再計算され、正解との**不足・余分・値違い・完了位置ずれ**が色で分かる

94ステージ / 12サイクル / 39オペレータ。ビルド不要、依存パッケージゼロ、`file://` でも動きます。クリアすると、あなたが組んだパイプラインが**そのまま RxJS のコードとして生成表示**されます。

判定は出力ストリームだけで行うので、`filter → map` と `map → filter` はどちらも正解になります。別解を潰さない設計です。

:::message
オペレータの意味論をどう決めたか（`takeLast` を Rx と変えた理由、`debounceTime` の完了時放出、`take` がエラーを消すのは Rx 準拠、など）は、それだけで1本になるのでここでは触れません。
:::

## 「動いた」時点では、まだ何も終わっていなかった

94ステージが遊べるようになった時点で、私は「できた」と思っていました。実際に残っていたのはこれだけあります。

- 音が何もない
- 日本語しかない
- ライセンスが決まっていない
- OG 画像も meta もない
- そもそも `git init` していない（公開 URL が存在しない）
- 数字を1つも取っていない
- 遊んだ人がどこにも辿り着けない

並べてみると分かるのですが、**どれも「作る楽しさ」がない領域**です。だから後回しになり、そのままローカルで腐ります。

そして**AIが一番効くのは、まさにここ**でした。以下、順に書きます。

### 音をつける

ElevenLabs の API で BGM と効果音を生成し、ffmpeg で無音トリムとラウドネス調整をかけました。ポイントは音そのものではなく、**生成プロンプトと後処理を全部スクリプトに残した**ことです。

```
tools/gen-audio.mjs   # プロンプト・尺・後処理チェーンをデータとして持つ
node tools/gen-audio.mjs          # 未生成分だけ作る
node tools/gen-audio.mjs --force  # 全部作り直す
```

既定でどこまで鳴らすかは迷いました。最初は「学習ツールで不意に音楽が鳴るのは最悪だ」と考えて BGM を既定オフにしたのですが、**それだと音をつけた意味がほとんど消えます**。スライダーをわざわざ上げる人はまずいません。結局、BGM も既定オンにして、効果音より十分低い音量から始める形に落ち着きました。ブラウザの自動再生規制があるので、実際に鳴り始めるのは最初のクリックかキー入力の後です。

ちなみに初稿の時点でAIは「両方オンでいい」と言っていました。**この件に関しては私が回り道をしただけ**でした。

そしてここで、思っていたより厄介な問題に当たりました。**生成したこの音源を、どのライセンスで配るのか。**

リポジトリはコードを MIT、ステージ定義や文書を CC BY 4.0 にしています。ではAI生成の音源は？ 調べていくうちに、原則はシンプルだと分かりました。

> **自分が持っていない権利は、再許諾できない。**

AI生成物の利用条件は生成元サービスとの契約に従います。私はその権利を保有していないので、第三者に「どうぞ使ってください」と言う立場にありません。そこで音源だけを CC BY の対象外として切り出し、`NOTICE.md` にこう書きました。

- これらの音源にはいかなる許諾も与えない
- 再利用したいなら**自分のアカウントで再生成してほしい**（`gen-audio.mjs --force` で同じプロンプトから作れる）
- あるいは ElevenLabs の規約を自分で確認してほしい

プロンプトを残しておいたおかげで、「配れないけど再現はできる」という着地ができました。**再現手順が資産で、生成物は副産物**、という整理です。

### 多言語にする

日本語と英語を切り替えられるようにしました。ここで守りたかったのは、**ステージ定義を純粋なデータのまま保つこと**です。将来 JSON に外出しできる形を壊したくなかった。

採った方法は、原本は日本語のまま置いて、英語は id をキーに上書きする形です。

```js
// STAGES は日本語のまま。JSON にそのまま出せる純データを維持する
const STAGES = [{ id: "stage-61", title: "Stage 61: 検索ボックス", ... }];

// 英語は別ファイルで id をキーに上書きするだけ
const I18N_STAGES_EN = { "stage-61": { title: "Stage 61: The search box", ... } };
```

HTML 側は `data-i18n` 属性で印を付け、マークアップには日本語の原文を書いたままにしてあります。**JSが動かなくても日本語では読める**状態を保つためです。

### 公開する

- コードは MIT、ステージ定義と文書は CC BY 4.0
- GitHub Actions で Pages にデプロイ（ビルドなし。静的ファイルを並べ替えるだけ）
- OG 画像、favicon、canonical、Twitter card
- **「非公式のファンプロジェクトであり ReactiveX / RxJS 公式とは無関係」の明記**

最後のは地味ですが重要です。名前が公式と紛らわしいものを海外に出すなら、先に潰しておく類のリスクです。

## 作った後をAIと詰める

ここからが本題です。公開した後、**「これをどう活かすか」をAIと検討しました**。誰に届けるのか、何のネタになるのか、自分の名前とどう繋げるのか。いわゆるセルフブランディングの設計です。

やり方は単純で、自分の状況（何を作ってきたか、どこで発信しているか、何に時間を使えるか）を渡して戦略メモを書かせ、**それを別のサブエージェントにレビューさせました**。1体は事実検証、もう1体は事業観点での批判役です。

結果、**初稿はかなり崩れました**。その崩れ方が面白かったので、以下に書きます。

## AIに検証させて分かったこと

### 1. AIは自分の文章を、コードを読み直して否定できる

初稿には「このゲームの判定エンジンは Rx に依存していないから、SQL やシェルパイプの教材にも横展開できる」と書いてありました。もっともらしい話です。

批判役に検証させたところ、**実測で潰されました**。

| 部位 | 行数 | 比率 |
| --- | --- | --- |
| 判定エンジン（`evaluatePipeline` + `diffStreams`） | **70行** | **1.6%** |
| オペレータの意味論（39種） | 588行 | 14% |
| ステージ定義（94問のレベルデザイン） | **2,364行** | **55%** |

横展開できるのは全体の 1.6%、しかもその70行はAIなら数十分で書き直せます。**資産の実体は残りの98%、つまり「意味論」と「レベルデザイン」に載っていた。**「エンジンが汎用だから量産できる」は、行数を数えた瞬間に消えました。

自分で書いた文章を、自分でコードを読み直して否定する。この使い方は素直に強いと思いました。

### 2. AIは「前提」を勝手に作る（そして誰もそれを疑わない）

これが一番の収穫です。

初稿には、**このゲームは私が自作したマルチエージェント基盤を使って開発した**、という筋書きが混ざっていました。「その基盤が実用に耐える証拠として使える」という、実に据わりの良いストーリーです。

**事実ではありませんでした。** このゲームは素の Claude Code に、音まわりの Agent Skills を3本足しただけで作っています。マルチエージェントは1回も使っていません。

しかも決定的なのは、**それを見抜いたのがレビュアーAIではなかった**ことです。リポジトリに `.team/` ディレクトリが無いことは、`ls` 一発で分かります。事実検証役のAIは39個のオペレータを数え直し、Zennの公開状態まで調べたのに、**この前提だけは誰も検証しに行きませんでした**。

一般化するとこうなります。

> AIは「**与えられた前提の中での整合性**」は検証できる。
> しかし「**前提そのものが現実と違う**」ことは疑わない。

以前、会社設立の登記をAIにやらせたときも同じことが起きました。レビュアーAIが「商業登記は本局に集中化されたので宛先はこちらが正しい」とネット知識で自信満々に指摘し、それを採用したら差し戻された。あのときと構造は同じです。**AIが検証するのは整合性であって、前提ではない。**

https://zenn.dev/hummer/articles/tosbec-incorporation-with-claude-code

そして、こういう前提のズレは**人間が一言「そもそもそれ使ってないんですけど」と言うだけで消えます**。ここが分業の線引きだと思っています。

### 3. 出口がなかった

指摘されて初めて気づいたのですが、**遊んだ人がどこにも行けない構造**になっていました。

ステージをクリアすると、自分が組んだパイプラインが RxJS のコードとして表示されます。プレイヤーが一番感心している瞬間です。**そこにリンクが1本もない。** ゲーム画面のフッターに GitHub リンクが1つあるだけでした。

作った本人は「公開した」で満足しているのに、遊んだ人から見ると**行き止まり**です。

クリア画面に一行だけ足しました。**94 ステージぶん毎回出すと雑音になる**ので、端末での初クリアと全クリアのときだけ出します。フッターには常設で置いてあります。

### 4. 「測る仕組み」は、設計だけあっても何も分からない

さらに間抜けだったのがこれです。

`docs/metrics.md` という計測設計のドキュメントを、実装より先に書いていました。何をなぜ測るか、重複をどう抑えるか、何を送らないか。我ながら丁寧に書けています。

**ところが、実装のスイッチが入っていませんでした。** アダプタの `provider` が `"none"` のまま公開していたので、送信は1バイトも発生していません。設計書だけがある状態です。

そこで Cloudflare Workers + D1 で収集基盤を自作しました。Cookie を使わず、IPも User-Agent 文字列も保存せず、端末種別と国コードだけを粗く残す構成です。Worker 側の本体はコメントを除いて100行ほどで、無料枠に収まります。

```
ブラウザ ──POST──> t.hummer98.dev/e (Workers) ──> D1
```

……で、終わりませんでした。**入れた直後に見にいったら、ゲーム側のイベントが1件も届いていません**。

犯人は `navigator.sendBeacon` でした。ページ遷移で取りこぼさないよう beacon を優先していたのですが、**`Content-Type: application/json` はクロスオリジンだとプリフライトが要る扱いになり、sendBeacon はプリフライトを扱えません**。しかも `sendBeacon()` は **`true` を返します**。キューに積んだ、という意味でしかないからです。送信側は成功に見え、受信側のログには何も残らない。

```js
// これは true を返すのに、届かない
navigator.sendBeacon(url, new Blob([json], { type: "application/json" }));

// text/plain なら単純リクエストになって通る（本文は JSON のままでよい）
navigator.sendBeacon(url, new Blob([json], { type: "text/plain;charset=UTF-8" }));
```

ついでにもう一段ありました。修正を出しても本番で直らない。GitHub Pages が `max-age=600` を返すので、**10 分間はブラウザが古い JS を掴んだまま**だったのです。単に反映が遅いだけでなく、新しい `app.js` と古い `i18n.js` が混ざる組み合わせが起こりえます。ビルド時に `?v=<コミット SHA>` を付けて解決しました。

「計測を入れた」と言えるまでに、**設計書 → 実装 → スイッチ → 実際に届いているかの確認**、と4段あったわけです。最後の1段を飛ばすと、数字がないことにすら気づけません。

## 教訓

**1. AIが一番効くのは、作るのが楽しくない領域だった。**

ライセンスの切り分け、多言語化、OG、計測、ディスクレーマ。実装よりもこちらの方が、AIに任せたときの体感の効きが大きい。個人開発が「動いた」で止まるのは、この領域に着手する気力が残っていないからです。

**2. AIに検証させると初稿は崩れる。ただし崩せるのは前提の中だけ。**

行数を数えさせる、実データを読ませる、公開状態を確認させる——事実の検証はAIの得意分野です。一方で、渡した前提が現実とズレていても、AIはその上に整合的な物語を積み上げます。**前提を疑うのは人間の仕事**として残ります。

**3. 「作った後どうするか」もAIと詰められる。ただしそれは相談であって、答え合わせではない。**

戦略メモは何度も書き換わりました。私が「そもそもそれ使ってない」「その導線先ならこっちでは」と口を挟むたびに、前提が入れ替わって結論も変わる。**壁打ち相手としては優秀ですが、正解を持っているわけではありません。**

## おわりに

「作る」のコストが下がったことは、もう十分に語られたと思います。個人的にいま面白いのは、**その次の「作りきる」のコストも同じくらい下がっている**ことです。音をつける、英語にする、ライセンスを決める、計測する、見せ方を決める。かつては全部が別のスキルセットで、だからこそ個人の作ったものはローカルで終わっていました。

出口と英語版はこの記事を書きながら片付けました。英語版は `?lang=en` で UI が切り替わるだけで、**canonical も OG も日本語のまま**——つまり検索にも SNS カードにも英語版が存在しない状態でした。クローラは JS を実行しないので、切り替えが効かないのは当然です。head だけ英語に差し替えた薄いコピーを `/en/` に生成し、日英を `hreflang` で相互に指すようにしています。

ゲーム自体は今日から遊べます。RxJS を書いたことがある人ほど、`debounceTime` と `auditTime` の違いあたりで手が止まると思います。
