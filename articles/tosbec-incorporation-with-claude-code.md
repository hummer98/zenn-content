## はじめに

2026年7月、1人株式会社を設立しました。定款の作成・公証人とのやり取り・登記書類の準備・資本金の払込証明まで、実務のほとんどを Claude Code に任せた結果、**実質2日で会社が立ちました**。世間では「登記日から逆算して2ヶ月確保しておけば安心」と言われる手続きです。

このプロセスで得たノウハウを Claude Code のスキル（プラグイン）として公開したので、その紹介です。

https://github.com/hummer98/tosbec-skill

## 前提: AIソロプレナーという働き方

本題の前に、なぜ登記をAIにやらせるのかという話をします。

私は1人でプロダクトを作って会社をやっていくつもりで、いわゆる「AIソロプレナー」の経営スタイルを設計しています。開発だけでなく、**バックオフィス業務（経理・法務・調達・スケジュール管理）も可能な限りAIエージェントに寄せる**という方針です。人を雇う代わりに、メール・ブラウザ・ファイルシステムに触れるエージェントを「事務担当」として運用する。

会社設立の登記は、その最初の本格的な実地テストとしてちょうどよい題材でした。理由は3つあります。

1. **書類仕事の塊である**。定款・登記申請書・決議書・就任承諾書・印鑑届出書…と書類が多く、相互に整合が要求される（住所表記の一字違いで差し戻される世界）
2. **非同期のメールプロセスである**。後述するTOSBECの添削はメールベースなので、メールを読み書きできるエージェントがそのまま回せる
3. **失敗のフィードバックが明確**。公証人・法務局担当者という「人間のレビュアー」が誤りを具体的に指摘してくれる

## TOSBECとは

東京開業ワンストップセンター（TOSBEC）は、国と東京都が共同運営する会社設立のワンストップ窓口です。定款認証から登記申請、税務・社会保険の届出までを1か所で、**何度使っても無料**でサポートしてくれます。

特徴的なのが運用フローです。

```
Web問い合わせ → オンライン初回相談(約20分)
  → 定款ブース・登記ブースから資料とひな型がメールで届く
  → 書類を作ってメールで送ると添削が返ってくる(数往復)
  → 添削完了後に来所予約 → 当日1.5時間で認証+申請 → 3営業日で登記完了
```

つまり**本体はメール添削の往復**です。ここがAIエージェントと決定的に相性が良い。エージェントにメールボックスの監視と書類の修正を任せると、往復のレイテンシがほぼゼロになります。実際、先方の返信から修正版の再送まで、人間の私がやったのは内容の承認だけという往復が何度もありました。

冒頭の「実質2日」の種明かしはこれです。書類一式を添削に出してから、両ブースの添削完了を経て登記申請の予約を確定するまでが実測2日。「2ヶ月確保」の正体は先方の処理時間ではなく、**申請者側の書類修正の滞留**なんですね。先方のレスポンスは速く（速いときは40分で返ってきます）、AIに任せるとこちらの修正も即座に終わるので、往復回数が多くても日数を食いません。私自身、初回相談のあと1ヶ月ほど放置していましたが、腰を上げてからは2日でした。会社実印の作成（納品まで1週間弱）だけは先に発注しておく必要があります。

## Claude Code が実際にやったこと

### メール監視と添削対応

himalaya（CLIメールクライアント）経由でGmailを読み書きさせ、TOSBECからのメールを定期チェック。添削指摘の要点抽出→書類修正→返信ドラフト作成→（人間が承認）→送信、というループを回しました。

地味に重要だった学び: **添削結果は元のスレッドへの返信で来るとは限らない**。「【氏名様】定款資料確認①」のような新規件名で届いたメールをスレッド監視から見落とし、丸1日気付かなかった事故がありました。ドメイン検索での監視が正解です。

:::message
エージェントにGmailを読み書きさせる手段としては、Google公式の [@googleworkspace/cli](https://github.com/googleworkspace/cli)（`gws`）が手軽でした。
:::

### 書類間の整合性チェック

送付前にサブエージェントにレビューさせたところ、「登記すべき事項」の事業目的が定款と**一字だけ**違う（「附帯」vs「付帯」）のを検出しました。目的は一字一句の一致が要求されるので、これはそのまま出していたら差し戻しコースです。

一方で失敗もありました。レビュアーAIが「商業登記は本局に集中化されたので宛先は東京法務局本局が正しい」とネット知識で自信満々に指摘し、それを採用して申請書の宛先を書き換えたら、**TOSBECから「港出張所宛に戻してください」と差し戻された**のです。ローカルな運用ルールはネットの一般知識より強い。AIの「もっともらしい訂正」を無批判に通すと、正しいものを壊すことがあります。

### セル入力できないExcel様式との戦い

法務局配布の印鑑届出書・印鑑カード交付申請書のExcel様式は、開いてみると**罫線もラベルも全部が図形描画**で、セルに値を入れる設計になっていません（openpyxlで見ると全セル空、結合セルもゼロ）。

Claude Code にやらせた解決策はこうです。

1. Excelからブランク様式をPDF書き出し（1ページに収まらず右下が切れる場合は、ページ設定を「横1×縦1ページに収める」にしてから）
2. `pdfminer.six` でPDF内のラベル文字（「年」「月」「□」「昭」…）の**グリフ座標を実測**
3. `reportlab` で記入テキスト・チェックの「レ」・丸囲みを描画し、`pypdf` で合成
4. Ghostscriptで200dpiレンダリング→該当行を拡大cropして検品

最初は座標を目測で合わせようとして何往復してもズレ続け、「自分でわからないんですか」と怒られました（ごもっとも）。**目測をやめて座標を実測し、検品も拡大画像で機械的にやる**ようにしたら一発で揃いました。エージェントに絵仕事をさせるときの一般則だと思います。

### 資本金の払込証明

ネット銀行にブラウザ（エージェントが操作するChromium）でログインし、口座情報画面と入出金明細のスクリーンショットを取得、体裁を整えたA4のPDFに自動組版しました。

ここで一番価値があったのは作業そのものより**要件の調査**でした。「残高があるだけではダメで入金記録が必要」「ただし複数回の入金の合算でよい」「定款作成日より前の入金も令和4年の通達で有効」——このあたりはネット上でも情報が錯綜していて、公式チェックリストと登記ブースへの質問で確定させました。危うく無意味な「一度引き出して入れ直す」振込手数料を払うところでした。

### 最大の見せ場: 設立日と決算期の罠

登記申請日（=会社成立日）を7/27に予約した後、人間の私がふと気付きました。「事業年度が8月開始だと、**第1期が7/27〜7/31の5日間で終わる**のでは？」

その通りでした。5日で決算・申告義務が発生し、消費税の免税期間（最初の2期）を約1年分捨てるところでした。Claude Code に影響分析をさせると、決算月を6月末に変更すれば設立日を動かさず第1期が約11ヶ月になると即答。定款の該当2条を修正して公証人に再送、で決着しました。

これは役割分担の好例だと思っています。**違和感に気付いたのは人間、影響の定量化と修正の実行はAI**。定款作成支援ツールは開始月を変えると附則を黙って再計算するので、ツールだけ使っていたら気付かなかった可能性が高い。

## ノウハウをプラグインにした

この一連で得た知見——フロー全体、両ブースの定型指摘、払込証明の要件、決算期の罠、図形Excel様式の攻略法——を `SKILL.md` に一般化して、Claude Code プラグインとして公開しました。

https://github.com/hummer98/tosbec-skill

インストールは2コマンドです。

```
/plugin marketplace add hummer98/tosbec-skill
/plugin install tosbec-skill@tosbec-skill
```

以後、Claude Code に「TOSBECで会社設立を進めたい」「定款の添削メールが来た」と話すと、このナレッジを踏まえて動いてくれます。プラグインの中身はスキル1個の最小構成（`strict: false` で `plugin.json` すら無し）なので、プラグイン配布のテンプレートとしても参考になるかもしれません。

## 注意

- 公証人は日替わりで、指摘内容にも個人差があります。**最終的にはTOSBECからの指示が正**です
